# Screen TUI 开发需求文档

- 版本：v0.1（草案，待评审）
- 依据：`README.md` 的 4 条核心功能 + `design/screen-capabilities.md` 的能力边界 + `design/reference-projects.md` 的横向分析
- 优先级记号：**P0** 必须在 v1 交付 / **P1** 应该交付 / **P2** 可延后 / **Won't** 明确不做
- 编号：`FR-xx` 功能需求，`NFR-xx` 非功能需求

## 1. 定位与目标

### 1.1 一句话定位

在 SSH（尤其是手机 SSH）里，把 GNU Screen 那套「记 PID、猜会话、敲一长串 `screen -r`」的操作，换成一块能看懂、能直接操作的面板。典型用途：**用 Screen 兜住 CodeX / Claude Code 这类长跑 AI 任务，SSH 断了任务不死。**

### 1.2 目标（v1）

1. 覆盖 README 列出的 4 条核心功能，一条不少。
2. 在**手机竖屏**上能用一只手完成「看一眼有什么在跑 → 挑一个 → 进去 → 出来」的完整闭环。
3. 在**桌面宽屏**上不显得浪费空间。
4. 兼容 GNU Screen 4.00.03 起的老版本（含 macOS 自带），能力缺失时降级而不是报错。
5. 服务器端安装成本接近「下载一个文件就能跑」。

### 1.3 非目标（v1 明确不做）

| # | 不做的事 | 理由 |
| --- | --- | --- |
| 1 | 向正在运行的会话注入按键 / 文本（`stuff`） | 用户会话里可能正跑着 AI 任务，静默写入不可接受 |
| 2 | 修改用户的 `~/.screenrc` 或往用户目录写任意文件 | 工具应该随时可删掉，不留痕 |
| 3 | 代管 systemd 服务 / 开机自启 | 越权重操作，非本工具职责 |
| 4 | 内嵌终端模拟器（PTY 自渲染） | 会把项目体量放大一个量级，与「零依赖小工具」冲突 |
| 5 | 多用户 / multiuser 会话管理 | 涉及权限与 setuid-root，v1 只读展示 |
| 6 | 自己实现终端复用（替代 screen） | 项目定位是 Screen 的前端，不是替代品 |

## 2. 用户与使用场景

| 优先级 | 场景 | 环境 | 关键诉求 |
| --- | --- | --- | --- |
| **P0** | 手机上查看 / 接管服务器上的 AI 长任务 | 手机 SSH 客户端（Termius、Blink 等），通常 40–80 列、20–40 行 | 少打字、数字键直选、信息极简、不卡顿 |
| **P0** | 桌面 SSH 日常管理多个会话 | 普通终端，通常 ≥100 列 | 一眼看清全部会话与状态、快速预览 |
| **P1** | SSH 登录后自动进入本工具 | `~/.zshrc` 条件触发 | 与直接敲 `screen -r` 一样快，不拖慢登录 |
| **P1** | 在脚本 / 管道里取会话列表 | 非交互 shell | 纯文本输出、稳定退出码、无 ANSI 转义 |
| **P2** | 排查「为什么 screen 用不了」 | 任意 | 一条命令给出体检报告与修复建议 |

## 3. 设计约束（贯穿全部需求）

| # | 约束 | 说明 |
| --- | --- | --- |
| C-1 | **非侵入** | 绝不向用户会话写入输入；预览走 `hardcopy` 只读快照；临时文件权限 0600 且退出即删 |
| C-2 | **老版本兼容** | 目标下限 GNU Screen 4.00.03；只依赖 `-ls` / `-dmS` / `-r` / `-x` / `-d` / `-X` / `-wipe` 这套 2006 年就存在的接口；`-Q` 仅作增强 |
| C-3 | **零/最小运行时依赖** | 不引入需要联网安装的运行时；优先单文件或单二进制 |
| C-4 | **手机优先** | 所有交互纯键盘可达、不依赖修饰键组合、不依赖鼠标 |
| C-5 | **不猜测** | 取不到的信息（如工作目录）留空或隐藏，绝不编造 |
| C-6 | **不动用户环境** | 不改 `.screenrc`、不装服务；配置只写标准位置（见 §8） |

## 4. 功能需求

### 4.1 P0 —— README 明确要求

#### FR-01 会话列表（README 第 2 条）

展示所有 Screen 会话，每条至少包含：**序号、会话名、状态**。

| 字段 | 来源 | 必需性 |
| --- | --- | --- |
| 会话名 | `screen -ls` 解析 | 必需 |
| 状态：可用 / 已占用 / 多端 / 已死 / 不可达 | `-ls` 状态词（`detached`/`attached`/`multi`/`dead`/`unreachable`） | 必需 |
| 创建时间 | `-ls`（**4.6+ 才有该列**，无则留空） | 可选 |
| 工作目录 / 运行命令 | `/proc`（Linux）或 `ps`/`lsof`（macOS） | 可选，取不到即隐藏 |
| 自定义别名 / 描述 | 本工具配置 | 可选 |
| 会话总数 | `-ls` 尾行或 `-q -ls` 退出码 | 必需 |

**验收标准**

1. 无会话时显示明确空状态与「按 `n` 新建」引导，而非空屏或报错。
2. 存在 dead 会话时在列表中标记，并提示可按 `W` 清理。
3. 名字超宽时截断，**顺序是先牺牲名字长度，绝不牺牲序号与状态**。
4. 解析层对「带日期列」与「无日期列」两种 `-ls` 格式均正确（用多版本样本回归验证）。

#### FR-02 新建会话（README 第 1 条）

**默认值优先**：名字一屏落地，目录与命令用默认值兜满，要改才展开。

| 参数 | 默认值 | 修改入口 |
| --- | --- | --- |
| 会话名 | 当前目录名，重名依次追加数字 | 表单内直接编辑 |
| 起始目录 | 启动 `stui` 时的 `$PWD` | `Tab` / `↑` / `↓` 切到 Directory 字段 |
| 启动命令 | `$SHELL`，取不到则 `/bin/sh`；**留空等于默认值** | 同上，切到 Command 字段 |

**验收标准**

1. 会话名默认值取当前目录名，重名时依次追加数字（`work` → `work2` → `work3`）。取名前先清洗目录名：空白转 `-`、去掉控制字符、剥去前导 `-` 与前导 `.`、目录名取不到时用 `session`、超长按 `NAME_MAX` 截断且不占用后缀空间。重名的判定范围是**当前会话列表（含 dead，dead 名依然占 socket 名）与配置里留档的会话名**。默认名可直接回车接受。
2. 会话名做校验：非法字符、超长、重名给出即时报错；重名允许创建但提示「将以 `<pid>.<name>` 寻址」。自动加数字只作用于**未被编辑过的**默认名；用户手打的重名不静默改名，仍只给提示。
3. 创建用 `screen -U -dmS <name> ...`，显式设置工作目录；`screen-256color` 可用时优先。
4. 创建成功后默认**直接连接进入**新会话（`defaults.attach_after_create` 默认 `true`）；置为 `false` 时停留列表并选中新会话。连接走 FR-03 的既有路径。两种情况下都**只在能确定「列表里那一个就是刚建的这一个」时才自动进入**：新会话没出现在枚举结果里、或同名会话多于一条（`-r <name>` 本身有歧义，取到的可能是早就存在的同名会话）时，都不猜 —— 改为在状态行说明「已创建，未自动进入」及原因，由用户自己选。
5. 创建失败（`screen` 不存在、目录不可写等）必须给出可行动的报错，不能静默。
6. 弹层是**单表单**：Name / Directory / Command 三字段同屏。`Tab` 与 `↓` 把焦点向后移、`↑` 与 Shift+`Tab` 向前移，到边界**循环回绕**。`Enter` 在任意字段生效：三字段整体校验，全过即创建；有错则焦点跳到第一个出错的字段并红字报错，改完再按。`Esc` 在任意字段取消整个向导回列表（草稿丢弃）。目录字段聚焦且收藏列表非空时 `1`–`9` 直选收藏目录填入（FR-23，选中后焦点不动）；其余字段里数字是普通字符。
7. 名字没改过时，提交前用最新枚举结果再确认一次名字：仍空闲就沿用用户看到的那一个，已被占用才换后缀，并在结果里说明换了哪个、为什么。
8. 后缀数字打满（`NAME_MAX` 与取号上限之内）仍全部被占时退回基名 —— 重名本身是允许的，由验收 2 的提示兜底，不为凑唯一而无限循环。

#### FR-03 连接已有会话（README 第 3 条）

按会话状态分派到正确的连接方式，用户不需要知道 `-r` / `-x` / `-d -r` 的区别。

| 选中状态 | 默认行为 | 可选行为 |
| --- | --- | --- |
| 可用（detached） | `screen -r` 接入 | 共享连接 `screen -x` |
| 已占用（attached） | **弹选择框** | `1` 共享连接（多屏同显 `-x`）／`2` 强制接管（踢掉对端 `-d -r`）／`Esc` 取消 |
| 多端（multi） | 同「已占用」，额外提示尺寸风险 | 同上 |
| 已死（dead） | **禁止连接** | 仅提示清理 |
| 不可达 | 禁止连接 | 仅提示 |

**验收标准**

1. 连接前**必须**打印 `Ctrl-A D` 返回提示（用户改过转义前缀时按实际前缀提示）。
2. 从会话 `detach` 出来后**自动回到本工具界面**并刷新列表 —— 头号体验契约，不允许退回 shell 让用户重敲命令。
3. 目标会话在启动后消失时，连接失败需明确提示并刷新，不抛异常不卡死。
4. 会话名不唯一导致 `screen -r` 拒绝时，自动回退 `<pid>.<name>` 全名重试。
5. 检测到已在 Screen 内（`$STY` 非空）时警告，说明 Screen 拒绝从自身内部 attach。

#### FR-04 小屏 / 宽屏双布局（README 第 4.1 条）

按终端宽度自动切换两套界面，也允许手动锁定。

| 档位 | 宽度 | 布局 |
| --- | --- | --- |
| 宽屏 | ≥ 100 列 | 左右双栏：左列表 + 右详情/预览；页脚 2 行含完整快捷键 |
| 中屏 | 72–99 列 | 单栏列表 + 详情区；页脚 1 行精简 |
| 窄屏 | < 72 列 | 单栏列表（序号 + 状态 + 名字）；页脚 1 行极简；无固定帮助区 |
| 极小 | < 50 列 或 < 15 行 | 只保留「序号 + 状态 + 名字截断」；帮助折叠为 `?` 弹层 |

`72` 取自 `tscreen` 的实测经验（手机 SSH 客户端常见宽度），阈值可配置。

**验收标准**

1. 旋转屏幕 / 调整终端大小后，下一次刷新即自动重排，无需重启。
2. **禁用自动换行，每行按显示宽度裁剪，宽度计算支持 CJK 与 emoji**（避免错行串行）。
3. 任何档位下都不出现水平滚动或内容溢出。

#### FR-05 小屏信息裁剪（README 第 4.2 条）

不只是换布局，而是**同一功能在不同尺寸下暴露不同粒度**。

| 信息 / 操作 | 宽屏 | 中屏 | 窄屏 |
| --- | --- | --- | --- |
| 序号 | ● | ● | ● |
| 状态图标 | 文字 + 图标 | 图标 | 图标 |
| 会话名 | 完整 | 完整（超宽截断） | 截断（保留前 12–20 字符） |
| 会话名后缀 `(Attached)` | 显示 | 显示 | 隐藏（并入状态图标） |
| PID | 显示 | 显示 | 隐藏 |
| 创建时间 | 显示 | 隐藏 | 隐藏 |
| 工作目录 | 显示 | 截断显示 | 隐藏 |
| 详情面板 | 常驻右栏 | 跟随选中 | 按 `i` 弹层查看 |
| 快捷键帮助 | 常驻页脚 2 行 | 页脚 1 行（高频键） | 隐藏，仅 `?` 弹层 |
| badge / 装饰 | 显示 | 显示 | 关闭 |

**验收标准**

1. 窄屏首屏必须能同时看到**至少 5 条会话**（在 40×20 这种极端尺寸下）。
2. 隐藏的信息必须仍可通过按键查看（不能是「看不到也没有别的入口」）。

### 4.2 P1 —— 从参考项目提炼的增强

#### FR-10 共享连接

用 `screen -x` 接入已连接的会话，实现手机与电脑**同屏共享**同一个会话（`tscreen`、`sm`、`screen-manager` 均支持）。

**验收**：在「已占用」会话上是显式的第一选项，且文案要讲清「另一端不会被踢掉」。

#### FR-11 强制接管

用 `screen -d -r` 断开对端后接入。

**验收**
1. 属于危险操作，需在选择框里明确标注「会踢掉另一端」。
2. **默认使用 `-d -r`，不使用 `-D -r`** —— 后者（power detach）会向父进程发 HUP，从登录 shell 启动时可能直接把用户登出。
3. `-D -r` 若提供，必须作为显式的高级选项并附风险提示。

#### FR-12 远程断开

用 `screen -X detach` 断开会话但**不进入**会话本身。`pouch` 与 `screen-manager` 都提供。

**验收**：操作后刷新列表，状态由「已占用」变为「可用」。

#### FR-13 终止会话（二次确认）

用 `screen -X quit` 终止会话。

**验收**
1. 必须二次确认，默认焦点在「取消」上（防止小屏误触）。
2. 确认框里显示**会话名 + 正在运行的命令**，让用户确认杀对了对象。
3. 不提供窗口级 `kill`（语义易误用，见 capability 文档陷阱 #12）。
4. dead 会话的清理走 `screen -wipe`，是独立操作、同样需确认。

#### FR-14 重命名会话

用 `screen -X sessionname <new>` 重命名运行中的会话。

**验收**：重命名后列表立即按新名显示；若本工具存有该会话的元数据，同步迁移键。

#### FR-15 会话预览（无侵入快照）

用 `screen -X hardcopy [-h] <tmpfile>` 抓取会话可见画面（`-h` 含回滚缓冲），读到内存后立即删除临时文件。

**验收**
1. 临时文件权限 0600，路径在用户可写的临时目录，**退出时无条件清理**（含异常路径）。
2. 预览内容做尾部空白裁剪，长行按宽度裁剪，不触发换行。
3. **`hardcopy` 不可用或失败时，明确显示「预览不可用」并保留元数据视图，绝不显示假内容或上一次的陈旧内容。**
4. 预览是只读操作，不改变会话状态（不 attach、不注入）。
5. 宽屏下预览常驻右栏并随选中项更新；窄屏下按 `p` 按需弹出。

#### FR-16 过滤 / 搜索

按会话名、运行命令、工作目录、PID 模糊匹配。

**验收**：输入即筛（无需回车）；`Esc` 清空；过滤状态在页脚可见。

#### FR-17 详情面板

展示选中会话的全部可得字段：会话名、PID、状态、创建时间、工作目录、运行命令、窗口数（`-Q windows` 可用时）、本工具存的自定义描述。

**验收**：`-Q` 不可用时，「窗口数」一栏隐藏而不是显示 `-` 或 `0`。

#### FR-18 返回提示

每次进入会话前打印 `Ctrl-A D` 提示（`pouch` 与 `screen-manager` 的共识做法）。

**验收**：若探测到用户改过转义字符（`.screenrc` 里的 `escape` / `-e`），提示要按实际前缀给出，而不是硬编码 `Ctrl-A`。探测不到则回退默认值并说明「若改过前缀请用你的前缀 + d」。

#### FR-19 刷新

手动 `r` 刷新 + 自动轮询。间隔可配置，默认 **3 秒**（介于 `spv` 的 1s 与 `screen-manager` 的 5s 之间）。

**验收**
1. 「有没有会话」的判定：`screen -q -ls` 退出码命中 `9` / `10` / `11+` 时可直接采信（快路径）；
   **不在表内的值一律视为不可判定并退回 `-ls` 文本明细**，两者矛盾时以文本为准。
   *（v0.2 修订：原文写「优先用退出码，比解析文本更抗版本差异」。M0 实测 4.00.03 空列表返回 **8** 而非 9，
   该表在最低兼容版本上不成立 —— 详见 `screen-capabilities.md` §4.3。）*
2. 刷新时**不闪屏、不丢选中项**、不重置过滤条件。
3. 连接会话期间**暂停轮询**（避免与用户操作打架）。

#### FR-20 dead 会话识别与清理

**验收**：`-ls` 中标记 dead 的会话用独立样式展示，并提供 `W` 触发 `screen -wipe`（含确认）。

#### FR-21 环境诊断 `doctor`

一条子命令输出体检报告。检查项见 §10。参照 `pouch doctor`。

**验收**：每项给出「通过 / 警告 / 失败 + 具体原因 + 可执行的修复建议」；退出码非 0 表示存在失败项。

#### FR-22 只读文本输出模式

`<tool> ls` 输出纯文本会话列表（无 ANSI、无边框），供脚本与管道使用（`tscreen ls`、`pouch ls` 的做法）。

**验收**
1. 在非 TTY 环境下自动切换为该模式，或在交互模式下直接给出明确报错（不得输出乱码控制序列）。
2. 支持稳定退出码：`0` = 有会话，`1` = 无会话，`2` = 环境异常。

#### FR-23 目录收藏与最近使用

记录新建 / 连接过的目录，按最近使用排序，新建会话时可直接数字键选（`sm` 的做法）。

**验收**：收藏数量上限可配（默认 10）；支持手输自定义路径并自动入收藏。

#### FR-24 会话元数据（别名 / 描述 / 启动命令）

为会话保存用户自定义别名、描述，以及（本工具创建的会话的）启动命令与工作目录，用于**重启**。

**验收**
1. 遵循 `pouch` 的模型：**本工具创建的会话 = managed（可重启）；用户已有的会话 = unmanaged（只连接，禁用重启）**。绝不假设有权重启别人的会话。
2. 会话消失后元数据不立即删除（避免误清理导致丢数据），采用可配置的 GC 策略或手动清理。

| FR-32 | 语义化标题 | 参照 `tscreen`：Linux 下走 `/proc` + agent 转录目录；**明确标注 Linux-only**，取不到则退化 |
| FR-33 | 工作区模式 | 参照 `scrn`：指向一个仓库目录，树状展示并自动建/连会话 |
| FR-34 | 窗口级操作 | 多窗口会话的窗口列表与切换（依赖 `-Q windows` 或 `-p`） |
| FR-35 | 剪辑板 / 会话内搜索 | Screen 原生有 `-X` 与 paste（不推荐在 v1 碰） |
| FR-36 | 双语界面 | 参照 `screen-manager` 的法英双语；中文为默认语言之一 |
| FR-37 | 鼠标支持 | Screen 4.7.0+ 才支持 SGR 1006；手机价值有限，仅桌面可选 |

## 5. 非功能需求

| # | 需求 | 指标 / 验收 |
| --- | --- | --- |
| NFR-01 | 依赖最小化 | 零第三方运行时依赖（或单二进制）；不得要求服务器联网安装包 |
| NFR-02 | 启动速度 | 冷启动到首屏 ≤ **200 ms**（不能拖慢 SSH 登录） |
| NFR-03 | 资源占用 | 常驻内存 ≤ 20 MB；空闲 CPU 占用 ≈ 0（轮询必须是非忙等） |
| NFR-04 | 版本兼容 | 覆盖 4.00.03 / 4.6+ / 4.9 / 5.0；能力缺失时降级并在 `doctor` 里说明 |
| NFR-05 | 纯键盘可操作 | 不依赖鼠标、不依赖 Ctrl/Alt 组合键；**核心操作只用一个字符键或数字键** |
| NFR-06 | 宽度安全 | CJK 与 emoji 显示宽度计算正确；禁用自动换行；行长钳制 |
| NFR-07 | 隐私与非侵入 | 不向会话写输入；预览临时文件 0600 且退出必删；不落盘任何会话内容 |
| NFR-08 | 竞态安全 | 每个动作执行前重新校验会话存在与状态（刷新间隔内会话可能消失） |
| NFR-09 | 非交互友好 | 无 TTY 时明确报错或切只读模式；只读模式输出可直接进管道 |
| NFR-10 | 可测试性 | 解析层与渲染层解耦；`-ls` 解析器需覆盖多版本样本的回归测试 |
| NFR-11 | 环境洁净 | 不改 `.screenrc`、不装服务、不写配置目录以外的地方 |
| NFR-12 | 国际化 | 全链路 UTF-8；中文与 emoji 正常显示，不出现方框或错位 |
| NFR-13 | 可安装性 | 单文件下载即用，或一条命令完成安装；卸载 = 删文件（+ 删配置目录） |

### 6.2 窄屏（< 72 列，手机）

```
 Screen TUI      3 sessions
 1 ▲ work
 2 ◆ llm
 3 ○ deploy
 4 ✕ legacy
 n new  # attach  ? help
```

要点：状态用**单字符图标**而不是 `(Attached)` 文字；不显示 PID / 时间 / 目录；帮助不在页脚展开。

### 6.3 状态图标（两套布局共用）

| 状态 | 图标 | 含义 |
| --- | --- | --- |
| detached | `○` | 可用，可直接接入 |
| attached | `◆` | 已占用，需选择共享或接管 |
| multi | `◈` | 多端连接中 |
| dead | `✕` | 已死，建议清理 |
| unreachable | `?` | 不可达，仅展示 |

图标选用**单字宽、无 emoji 变体**的字符（emoji 在部分终端是双宽，会破坏对齐，见 NFR-06）。

### 6.4 按键表

| 键 | 动作 | 窄屏是否暴露 |
| --- | --- | --- |
| `1`–`9` | 直接连接对应序号的会话 | ✅ 核心 |
| `j` / `k` / `↑` / `↓` | 移动选中 | ✅ |
| `Enter` | 连接选中会话 | ✅ |
| `n` | 新建会话 | ✅ |
| `x` | 共享连接 | ✅ |
| `p` | 预览 | ✅ |
| `i` | 详情弹层 | ✅（窄屏主要入口） |
| `D` | 远程断开 | ✅ |
| `K` | 终止（需确认） | ✅ |
| `r` | 重命名 | 宽屏 |
| `W` | 清理 dead 会话（需确认） | 宽屏 |
| `/` | 过滤 | ✅ |
| `R` | 手动刷新 | 宽屏 |
| `?` / `h` | 帮助弹层 | ✅ |
| `q` / `Esc` | 退出 | ✅ |

**新建向导内**（单表单，任意字段位置都能直接创建）：

| 键 | 动作 |
| --- | --- |
| `Enter` | 校验三字段并创建（任意字段位置生效；失败时焦点跳到出错字段） |
| `Tab` / `↓` / `↑` | 在 Name / Directory / Command 之间循环切换焦点（Shift+`Tab` 反向） |
| `1`–`9` | 目录字段聚焦且收藏列表非空：直选收藏目录填入；其余时候是普通字符 |
| `Esc` | 取消向导回列表（草稿丢弃） |

**设计规则**：核心动作用**小写单字符或数字**；大写键（`D`/`K`/`W`/`R`）只留给危险或低频操作，因为手机键盘打大写要切 Shift。危险操作的小写别名（如 `k` = kill 的常见约定）必须重新分配，避免误触。

## 8. 配置与数据

### 8.1 位置

| 内容 | 路径 | 覆盖方式 |
| --- | --- | --- |
| 配置 + 元数据 | `$XDG_CONFIG_HOME/screen-tui/config.json`（默认 `~/.config/screen-tui/`） | 环境变量 `SCREEN_TUI_HOME` |
| 预览临时文件 | `$TMPDIR/screen-tui-preview-<pid>` | 权限 0600，退出即删 |
| 状态（最近使用等） | 与配置同目录 `state.json` | 可禁用（`--no-state`） |

### 8.2 结构草案

```json
{
  "version": 1,
  "ui": {
    "layout": "auto",
    "narrow_cols": 72,
    "wide_cols": 100,
    "refresh_ms": 3000,
    "icons": true
  },
  "defaults": {
    "use_utf8": true,
    "prefer_256color": true,
    "attach_after_create": true,
    "escape_prefix": "C-a"
  },
  "dirs": [
    { "path": "/srv/app", "last_used": "2026-09-23T14:02:00+08:00" }
  ],
  "sessions": {
    "work": { "alias": "登录修复", "note": "claude 任务", "managed": true,
              "command": "claude", "cwd": "/srv/app" }
  }
}
```

### 8.3 要求

1. 写入必须**原子**（写临时文件 + `rename`），避免中断产生半截配置。
2. 权限 0600（目录 0700）。
3. `version` 字段用于后续迁移；读到未知高版本时不覆写，给出警告后只读运行。
4. 配置文件损坏时**不得崩溃**：备份为 `.bak` 后用默认值启动并提示。
5. 不写入会话内容、不缓存预览文本到磁盘。

## 9. 主流程与状态机

```
                    ┌──────────────┐
启动 ──► 环境自检 ──►│ 自检失败      │ → 错误屏（原因 + 修复建议 + doctor） → 退出码 2
                    └──────────────┘
        │通过
        ▼
   ┌─────────────┐  n   ┌──────────┐  创建成功  ┌────────────┐
   │  主列表      │─────►│ 新建向导  │───────────►│ 回列表/连接 │
   │ (轮询 3s)    │      └──────────┘            └────────────┘
   └──────┬──────┘
          │ Enter / 数字键
          ▼
   ┌──────────────────┐
   │ 校验会话仍存在？  │── 否 → 提示 + 刷新 + 回列表
   └────────┬─────────┘
            │是
            ▼
   ┌──────────────────┐
   │ 状态分派          │
   │ detached → 直接接 │
   │ attached → 选择框 │── 1 共享(-x) / 2 接管(-d -r) / Esc 取消
   │ dead     → 拒绝   │
   └────────┬─────────┘
            ▼
   打印 Ctrl-A D 提示 ──► 让出终端 ──► exec screen
                                        │ detach
                                        ▼
                                  恢复界面 + 刷新列表  ← 头号体验契约
```

**退出路径**：任何界面下 `q` / `Esc` 回上一层；主列表下 `q` 退出且恢复终端原始状态（raw mode、光标、备用屏幕缓冲区必须还原 —— 异常退出也要还原）。

## 10. 环境诊断（FR-21）检查项

| # | 检查项 | 方法 | 失败时的修复建议 |
| --- | --- | --- | --- |
| 1 | `screen` 是否可执行 | `which screen` | `apt install screen` / `yum install screen` / `brew install screen` |
| 2 | 版本 | `screen -v` 解析 | 低于 4.6 时说明「查询类功能将降级，不影响核心功能」 |
| 3 | socket 目录可访问 | `screen -ls` 是否成功 | 检查 `SCREENDIR` / `TMPDIR` 是否被误设为空（实测踩过这个坑） |
| 4 | 会话枚举 | `screen -q -ls` 退出码 | `9` 无会话（正常）/ `10` 有会话但不可连接（需检查权限）/ `11+` 正常 |
| 5 | terminfo | `infocmp screen-256color` | 缺失时提示安装 `ncurses-term`，本工具退化为 `screen` |
| 6 | UTF-8 | `locale` 与 `-Q info` | 提示 `.screenrc` 加 `defutf8 on`（**只建议，不代写**） |
| 7 | 死会话 | `-ls` 是否含 `dead` | 建议执行 `screen -wipe` |
| 8 | 是否在 Screen 内 | `$STY` | 提示嵌套限制与 `-x` 语义 |
| 9 | 终端尺寸 | `ioctl(TIOCGWINSZ)` | 尺寸异常时提示布局无法确定 |
| 10 | 配置可写 | 试写并删除临时文件 | 提示配置目录权限问题 |
| 11 | 预览能力 | 试 `hardcopy` 到临时文件 | 失败时说明预览功能将不可用及可能原因 |

## 11. 版本兼容策略

1. **一处探测，全局使用**：启动时跑一次 `screen -v`，得到 `(major, minor, patch)`，写入能力对象。
2. **能力开关而非版本分支**：代码里判断的是 `caps.query` / `caps.hardcopy` / `caps.truecolor`，不是 `if version >= "4.6"`。
3. **降级必须可见**：功能被降级时在 `doctor` 与帮助弹层里说明原因，不用静默隐藏代替解释。
4. **兼容下限** 4.00.03（macOS 自带 / 老发行版），**上限**不设限，靠能力探测自适应。
5. **解析器多版本回归**：至少准备 4 份 `-ls` 样本（4.00.03 无日期 / 4.6+ 有日期 / 无会话 / 含 dead + unreachable），作为单元测试固定用例。

## 12. 技术选型

> **已确认（2026-09-23）：Rust 单二进制**，详见 [`tech-design.md`](./tech-design.md)。以下保留备选分析作为决策依据。

| 方案 | 优势 | 代价 | 结论 |
| --- | --- | --- | --- |
| **Rust 单二进制** | 单文件分发、启动最快、资源最省、类型安全；Docker 交叉编译覆盖 Linux 双架构 | 需预编译分发；迭代成本高于脚本 | **✅ 采用** |
| Python 单文件 | 零编译、服务器必有 Python 3 | 性能与真彩一般；需要目标机有解释器 | 否 |
| Go 单二进制 | Bubble Tea 生态成熟（`spv` 已验证） | 需预编译二进制；引入第三方 TUI 库 | 否 |
| Node + Ink | 组件化体验好（`sm`/`tscreen` 已验证） | 要求 Node 18+，与 NFR-01 冲突 | 否 |

注：NFR-01「零第三方运行时依赖」的确切含义是**运行时零依赖**（静态二进制，无解释器/动态库要求）；编译期 crate 依赖不受限。
